从真实故障，到可审阅的修复。

  1. 报告问题

    将可复现故障及脱敏证据记录为本地 Issue。

  2. 复现故障

    关联一项聚焦的回归测试，明确需要改变的行为。

  3. 执行修复

    DeepSeek Harness 在独立分支中修复，并运行关联测试。

  4. 审阅变更

    检查本地 PR、Diff、测试与 Run，再批准合并。

  5. 保留经验

    把结果与 Wiki 记录留给后续 Agent 和会话。

SkillHone 把每次开发步骤表示为结构化的决策记录。当任务和环境变化时，后续 Agent 可以查阅既有历史，判断相似修复是否尝试过，以及某个方案为何被否决。

论文中的优化与评估角色拥有不同权限。优化方使用脱敏反馈修订 Skill，评估方保留原始评估材料，二者通过调度器交换结果。

开始之前，你可能想知道。

已经有 Skill 了，还能用吗？

可以。SkillHone 从现有 Skill 仓库与故障或评估证据出发；修订可以覆盖说明、脚本、引用、资源与测试，同时留下每次尝试的判断。

支持哪些 Agent？

本地 CLI 不绑定某一种 Agent。安装文档覆盖 Codex、Claude Code、Cursor、Pi 和 ZCode，其他能够调用 CLI 的 Agent 也可以使用同一工作流。DeepSeek Harness 承担修复执行。

会自动合并或 push 吗？

默认先审阅。自动本地合并需要主动开启，而且关联测试必须通过；push 是用户单独授权的操作。以复制模式导入的 Skill 还需要明确同步回原安装位置。

论文提升是否等于每次修复的提升？

论文数字对应其数据集、设置和基线。实际修复应通过关联的回归测试，或使用独立评估器测量效果。

SkillHone 使用 DeepSeek Harness 作为修复执行器，在独立分支上完成修改并运行关联测试。SkillHone 将本地 PR、验证证据与决策历史保存在一起。
